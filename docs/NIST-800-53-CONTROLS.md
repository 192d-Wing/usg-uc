# NIST 800-53 Rev5 Control Implementation Matrix

This document maps NIST 800-53 Rev5 security controls to their implementations in the USG SBC codebase.

> **Status legend.** *Wired (sbc-daemon | sbc-media-core | soft client)* — a shipped binary has a call site for this (the binary is named). *Library-only* — implemented and tested in a `proto-*`/`uc-*` crate, but no shipped binary calls it. *Planned* — not implemented. A row that says only "Full"/"Complete" describes crate-level capability; the wiring column/annotation says what the running SBC actually does.

Crate names below are the real workspace crates (`crates/uc/uc-*`, `crates/proto/proto-*`, `crates/sbc/*`). There are no `sbc-crypto`, `sbc-audit`, `sbc-acl`, `sbc-registrar` or similar crates.

## Control Families

| AC-2 / AC-2(4) | Account Management / Automated Audit Actions | **Wired (sbc-api-server)** for the `/users` table | Create, update and delete on `/api/v1/users` require `users:admin` (see AC-3 / AC-6). Every attempt, success or failure (including a rejected JSON body, reason `invalid`), emits a `uc-audit` `AccountManagement` record (`uc-audit/src/event.rs`, emitted from `sbc-api-server/src/handlers/users.rs`): actor, optional `actor_issuer` (OIDC issuer), action `Create`/`Update`/`Delete`, `target_user_id`, `target_username`, `success`, fixed-token `failure_reason`, `changed` (field-group names only: `password`, `enabled`, `username`, `profile`; omitted when empty), and `source_ip` (trusted-proxy aware), in the standard record envelope (sequence, UTC timestamp, hash chain). The `uc-acl` crate is Library-only (no shipped binary depends on it). **sbc-api-server `/users`:** the five routes are mounted under `require_auth` with route layers for `users:read` (GET) and `users:admin` (POST/PUT/DELETE) (`handlers/users.rs` `routes()`, `authmw.rs`); a denial returns 403 and is audited as `AuthorizationDecision` with policy `users-rbac`, and no `AccountManagement` record is written. | AU-4 | Audit Log Storage Capacity | Not met in-process; capacity is the platform's | `uc-audit::sink::FileSink` appends JSON lines to one file: `logging.audit_path` (sbc-daemon), `SBC_API_AUDIT_PATH` (sbc-api-server) or `CENTRAL_API_AUDIT_PATH` (central-config-api). Without a path records go to the tracing output (target `audit`). There is no rotation, retention, free-space check or capacity alert (POA&M-133); a full volume shows up only as write failures (see AU-5). |
| AU-5 | Response to Audit Logging Process Failures | **Wired (sbc-daemon)**, opt-in | Audit hand-off is non-blocking: `uc_audit::log_event` only `try_send`s onto a bounded queue of `AUDIT_QUEUE_CAPACITY = 4096` records drained by a dedicated `uc-audit-writer` thread, which assigns sequence numbers and the hash chain in queue order (`uc-audit/src/lib.rs`). Failure response: when the queue is full or the writer has exited, the record is **dropped and counted** (`dropped_records()`), and `log_event` emits a `tracing::error!` rate-limited to once per 10 s. Sink writes are fallible (`AuditSink::write -> io::Result<()>`): a failed write does not advance the sequence or hash, is counted in `write_failures()` and `dropped_records()`, sets `sink_failing()` until a write succeeds, and logs a rate-limited error. Loss is recorded in the chain: queue-full drops, sink write failures and a torn file tail become `AuditRecordsDropped { count, total, reason }` records (Security category; `reason` = `queue_full`, `sink_write_failed` or `torn_tail`), emitted when the writer next persists a record; a marker whose own write fails stays pending and is not counted as loss. Records dropped while the writer is dead cannot be chained (health is already unhealthy). A guard clears `writer_alive()` when the writer exits, including by panic. The daemon health check has an `audit` component: unhealthy when the writer is dead, or while `sink_failing()` is set; degraded only while the most recent drop or write failure is less than `AUDIT_DROP_DEGRADED_WINDOW` (60 s, a constant, not configurable) old, then healthy again (`api_server.rs` `audit_status_from`/`audit_component_status`, using `uc_audit::last_drop_elapsed()`). The `sbc_audit_records_dropped` gauge stays cumulative and is never reset, so a drop burst that ends more than 60 s before a health poll is visible only in the counter: operators must alert on the rate of increase of `sbc_audit_records_dropped`, not on health status alone. Gauges `sbc_audit_records_dropped` (queue drops plus write failures), `sbc_audit_write_failures`, `sbc_audit_writer_alive` and `sbc_emergency_calls_admitted` are refreshed in gRPC `GetMetrics`. On shutdown, after `SystemShutdown`, `runtime.rs` calls `uc_audit::flush` with a 2 s deadline (it retries queuing its marker until the deadline, so a full queue is waited on). Records still queued when the deadline passes are lost. Fail closed at startup: when `logging.audit_path` is set and `FileSink::open` fails (including a refused symlink, non-regular file, group/world-writable directory or torn-only file), sbc-daemon logs the path and reason and `Runtime::new` returns `RuntimeError::AuditFailed`; `main.rs` exits with `AUDIT_INIT_FAILED_EXIT_CODE` = 3 (`runtime.rs` `init_audit`, `RuntimeError::exit_code`; other init errors exit 1). Unset `audit_path` keeps tracing-only output. sbc-api-server and central-config-api fail closed when their audit path is set but cannot be opened (sbc-api-server exit 5, shared with its runtime server error; central-config-api exit 6), and `/readyz` reports not-ready while the sink is failing (central-config-api also when the writer is dead). Tests: `failing_sink_counts_and_does_not_advance_chain`, `failed_marker_write_stays_pending_without_counting`, `queue_drops_become_one_marker`, `failing_sink_is_unhealthy_counted_and_marked_in_chain` (`uc-audit/tests/sink_failure.rs`), `audit_status_unhealthy_when_sink_failing`, `audit_status_degraded_after_recent_write_failure`, `not_ready_when_audit_sink_failing` (sbc-api-server), `init_audit_bad_path_is_error` (both API servers, and sbc-daemon `runtime::tests::init_audit_bad_path_is_error` asserting `AuditFailed` and exit code 3), `runtime::tests::audit_exit_code_is_distinct` (sbc-daemon; the exit-code mapping in `main()` is not tested, nor central-config-api `/readyz` with a failing sink), `queue_full_drops_are_counted_and_chain_stays_contiguous`, `concurrent_writers_keep_contiguous_verified_chain_and_flush_drains`, `flush_with_full_queue_waits_for_drain`, `writer_dead` tests (`uc-audit/tests/`), `global_logger_queues_records_in_order_with_hash_chain`, `health_and_metrics_expose_audit_pipeline_and_emergency_admissions`, `writer_drop_recency` (`uc-audit/tests/writer_drop_recency.rs`), `elapsed_since_encodes_never_as_none`, `audit_status_recovers_after_drop_window`, `qa_audit_status_window_boundary`. Not tested: the health endpoint JSON for a degraded `audit` component over HTTP, and the metrics gauge after recovery (its source is unchanged). STIR aggregator: when its key table is full (`MAX_KEYS`) new keys are dropped and counted (`stir_audit_events_dropped_total`); each flush that sees the count increase logs `warn!` and emits `StirAuditEventsDropped { count, total }` (Security category). Tests: `full_table_drops_and_counts`, `dropped_audit_events_are_reported_per_flush`. |
| AU-8 | Time Stamps | **Wired (sbc-daemon)**, opt-in | `uc-audit::record` UTC timestamps from the system clock, stamped in the writer thread when the sequence number is assigned, so timestamps are non-decreasing in sequence order unless the wall clock steps backwards (not clamped; asserted for a normal clock in `uc-audit/tests/sink_failure.rs`). | AU-9 | Protection of Audit Information | **Wired (sbc-daemon, sbc-api-server, central-config-api)**, opt-in, partial: tamper-evident only | `uc-audit::record` unkeyed SHA-384 hash chain across records. `FileSink::open` (`uc-audit/src/sink.rs`) resumes sequence and hash from the last complete canonical record in the final 1 MiB of the file, so the chain continues across restarts; an unterminated tail fragment is truncated and a `torn_tail` marker is chained first. A non-empty file with no valid record (including one holding only a torn fragment) is refused (`InvalidData`) and left untouched. New files are 0640; missing directories are created 0750; an existing audit file with wider bits is tightened to 0640 only after a valid record is found. Refused: a symlink (including a dangling one) or non-regular path, a group- or world-writable parent directory (`PermissionDenied`), and an opened fd whose dev/ino does not match a fresh lstat. A residual race remains because the open does not use `O_NOFOLLOW` (POA&M-131). `uc_audit::verify` and `sbc-cli audit verify <FILE>...` check offline that every line is the canonical serialisation of its record (`record::parse_canonical`, `deny_unknown_fields`), sequences are contiguous and hashes link across the files given; `--require-anchor` fails when the first file does not start at genesis (otherwise it prints `WARN UNANCHORED`). The verifier stops at the first bad line, so records after it are not verified; resume skips non-canonical lines and leaves them in the file, so later records in that file are not verifier-checked until the file is investigated (SEC-004, advisory). Anyone with write access can rewrite the file and recompute the chain; there is no key or signature (POA&M-130). Tests: `file_sink_resumes_chain_across_restart`, `global_logger_continues_chain_from_existing_file`, `resume_truncates_unterminated_tail_and_marks_unclean`, `resume_skips_unparsable_complete_lines_as_unclean`, `resume_skips_non_canonical_line`, `resume_fails_on_non_empty_file_without_records`, `foreign_file_is_not_modified`, `symlink_is_refused_and_target_untouched`, `writable_directory_is_refused`, `files_are_0640_in_0750_directory`, `file_sink_truncates_torn_write`, `logger_resumes_and_marks_torn_tail_first`, `verify_ok`, `tamper_one_byte_detected`, `deleted_line_detected`, `reordered_lines_detected`, `non_canonical_bytes_rejected`, `bad_hex_line_reported_not_panic`, `unanchored_start_accepted_links_checked`, `multi_file_continuation`, `long_line_rejected`, `torn_final_line_rejected`, `hex_odd_length_errors`, `hex_multibyte_errors`, `audit_verify_passes_then_fails_on_tamper`, `verify_exit_codes_ok_tampered_reordered_deleted_missing` (`sbc-cli/tests/audit_verify_exit.rs`). Not tested: the exact 0750 mode under a permissive umask. |
| AU-10 | Non-repudiation | Planned | Cryptographic signing of audit records. Neither the uc-audit chain nor the CDR SHA-384 chain and sidecars provide AU-10: both are unkeyed and unsigned (uc-audit keyed chain or signed checkpoints is POA&M-130; CDR signing is POA&M-13). A passing `sbc-cli audit verify` shows self-consistency, not authorship. |
| AU-12 | Audit Record Generation | **Wired (sbc-daemon, sbc-api-server, central-config-api)**, opt-in | Each binary initialises the global uc-audit writer; the API servers read their file path from `SBC_API_AUDIT_PATH` / `CENTRAL_API_AUDIT_PATH` (absolute; empty means unset; relative is rejected) and load config before audit init. ### Call Detail Records (uc-cdr, sbc-daemon, sbc-api-server)

CDRs (schema v1) are a second audit trail next to uc-audit. `uc-cdr` provides the record, formats, hash chain, PII policy, ring and sinks. `sbc-daemon/src/cdr.rs` and `sip_stack.rs` emit the records. `sbc-daemon/src/grpc_server/cdr_service.rs` serves them over gRPC. `sbc-api-server/src/handlers/cdrs.rs` and `authmw.rs` serve them over REST. `[cdr]` is enabled by default. Rows here describe CDR behaviour only; the uc-audit rows above are unchanged. No test runs a real daemon process with SIP endpoints, REST through sbc-api-server, or a real TLS handshake on the gRPC or syslog channels. The daemon-level tests drive `SipStack` with a file sink.

| Control | Title | Status | Implementation |
|---------|-------|--------|----------------|
| AU-2 / AU-12 | Event Logging / Audit Record Generation | **Wired (sbc-daemon)**, on by default | One CDR per call when it ends. Answered, cancelled, busy/trunk 4xx-6xx, Timer B, transport error, media failure and shutdown endings emit through `finish_call_record` / `cleanup_terminated_call` (`sip_stack.rs`). Reject CDRs (`CdrContext::emit_rejected`, `cdr.rs`) are written for 503 draining, 503 `reject_new_calls`, 503 `max_calls`, VPS rejects, 503 no usable trunk, 500 invalid translation and the no-route announcement. They are de-duplicated per Call-ID: a bounded FIFO of 8192 entries with a 32 s TTL. ACL/DoS drops and the source-admission 403 produce no CDR; the 403 is audited only in uc-audit (`audit_invite_denied`). A 401/407 trunk challenge produces a CDR only with `record_auth_challenges = true`. `record_unanswered = routed` skips pre-store rejects, and `none` skips every unanswered call. Disabling `[cdr]` is an AU-12 deviation. Tests: `cdr_answered_then_caller_bye`, `cdr_answered_then_callee_bye_with_q850`, `cdr_cancel_before_answer`, `cdr_trunk_busy`, `cdr_timer_b_on_last_trunk`, `cdr_media_failure_after_answer`, `cdr_failover_then_answer_lists_trunk_attempts`, `cdr_bye_cancel_race_emits_exactly_one`, `cdr_trunk_407_is_not_recorded_unless_configured`, `cdr_register_challenge_is_not_recorded`, `cdr_reject_sites` (403 produces no CDR; a 503 INVITE sent three times produces one CDR), `cdr_no_route_announcement_is_a_reject`, `cdr_no_usable_trunk_is_a_no_route_reject`, `cdr_record_unanswered_routed_skips_rejects`, `cdr_shutdown_ends_remaining_calls`. ## Implementation Notes

### Documenting Controls in Code

All security-relevant code includes NIST control references in doc comments:

```rust
/// NIST 800-53 Rev5: SC-13 (Cryptographic Protection)
///
/// Computes SHA-384 hash of the input data.
pub fn sha384(data: &[u8]) -> [u8; 48] {
    // ...
}
```

### Verification

Control implementations are verified through:

1. **Unit Tests**: Each module has tests validating correct behavior (e.g. `sbc-config/src/validate.rs`, `sbc-daemon/src/sip_stack.rs` admission tests).
2. **Integration Tests**: `crates/sbc/sbc-integration-tests`. There is no `tests/compliance/` directory.
3. **Audit Logging**: Wired, opt-in via `logging.audit_enabled` (see AU-2). Without it, security events are visible only in `tracing` output.
