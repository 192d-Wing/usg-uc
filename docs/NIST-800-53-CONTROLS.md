# NIST 800-53 Rev5 Control Implementation Matrix

This document maps NIST 800-53 Rev5 security controls to their implementations in the USG SBC codebase.

> **Status legend.** *Wired (sbc-daemon | sbc-media-core | soft client)* — a shipped binary has a call site for this (the binary is named). *Library-only* — implemented and tested in a `proto-*`/`uc-*` crate, but no shipped binary calls it. *Planned* — not implemented. A row that says only "Full"/"Complete" describes crate-level capability; the wiring column/annotation says what the running SBC actually does.

Crate names below are the real workspace crates (`crates/uc/uc-*`, `crates/proto/proto-*`, `crates/sbc/*`). There are no `sbc-crypto`, `sbc-audit`, `sbc-acl`, `sbc-registrar` or similar crates.

## Control Families

### AC - Access Control

| Control | Title | Status | Implementation |
|---------|-------|--------|----------------|
| AC-3 | Access Enforcement | **Wired (sbc-daemon)** | INVITE source admission: the source IP must belong to a configured trunk or an active registration contact (`sbc-daemon/src/sip_stack.rs`, `is_admitted_source`). The `uc-acl` crate is Library-only (no shipped binary depends on it). |
| AC-6 | Least Privilege | Planned | `uc-acl` crate exists (Library-only); not wired into any binary. |

### AU - Audit and Accountability

| Control | Title | Status | Implementation |
|---------|-------|--------|----------------|
| AU-2 | Event Logging | **Wired (sbc-daemon)**, opt-in | With `logging.audit_enabled`, `sbc-daemon` initialises `uc-audit` (`runtime.rs`) and records startup/shutdown, REGISTER authentication outcomes, INVITE admission/VPS rejections, emergency-bypass grants, call establishment/termination and rate-limit rejections (`sip_stack.rs`, `server.rs`). Trunk failover is recorded as `TrunkFailover` (`sip_stack.rs` `try_failover`, emitted after the router guard is dropped) with reason 503/5xx status, `timeout` (Timer B) or `transport_error`. Trunk reachability changes are recorded as `TrunkReachabilityChanged` with source `options` (runtime OPTIONS health feed, `runtime.rs`) or `agent` (gRPC `trunk_status_publish_service.rs`), both through `SipStack::apply_trunk_reachability_change`. Tests: `status_failover_is_audited_with_status_reason`, `qa_timer_b_failover_is_audited_with_timeout_reason`, `send_failure_fails_over_once_without_waiting_for_timer_b` (transport_error), `reachability_change_is_audited` (calls the shared helper directly; the runtime and gRPC call sites are not driven by a test). Off by default. |
| AU-3 | Content of Audit Records | **Wired (sbc-daemon)**, opt-in | `uc-audit::record` structured records (sequence, UTC timestamp, typed event, hash chain) written for every event above. `AuthorizationDecision` has an additive optional `source_ip` (`uc-audit/src/event.rs`; omitted from JSON when absent, old records still deserialise), populated at every `AuthorizationDecision` site in `sip_stack.rs`: source-admission, `vps:*`, `no-usable-trunk`, `number-translation-invalid`, `max-registrations` and `emergency-bypass`. New `System`-category events: `TrunkFailover { call_id, group_id, failed_trunk_id, reason, next_trunk_id }` and `TrunkReachabilityChanged { trunk_id, reachable, source }` (`event.rs`). Tests: `authorization_decision_source_ip_is_additive`, `trunk_events_serialize_and_categorize`, `denials_carry_source_ip_in_audit`, `emergency_call_placed_while_callee_cap_max_calls_and_trunks_full`. |
| AU-4 | Audit Log Storage Capacity | **Wired (sbc-daemon)**, opt-in | `uc-audit::sink::FileSink` appends JSON lines to `logging.audit_path`; without a path records go to the tracing output (target `audit`). Rotation/retention is the platform's. |
| AU-5 | Response to Audit Logging Process Failures | **Wired (sbc-daemon)**, opt-in | Audit hand-off is non-blocking: `uc_audit::log_event` only `try_send`s onto a bounded queue of `AUDIT_QUEUE_CAPACITY = 4096` records drained by a dedicated `uc-audit-writer` thread, which assigns sequence numbers and the hash chain in queue order (`uc-audit/src/lib.rs`). Failure response: when the queue is full or the writer has exited, the record is **dropped and counted** (`dropped_records()`), and `log_event` emits a `tracing::error!` rate-limited to once per 10 s. A guard clears `writer_alive()` when the writer exits, including by panic. The daemon health check has an `audit` component: unhealthy when the writer is dead; degraded only while the most recent drop is less than `AUDIT_DROP_DEGRADED_WINDOW` (60 s, a constant, not configurable) old, then healthy again (`api_server.rs` `audit_status_from`/`audit_component_status`, using `uc_audit::last_drop_elapsed()`). The `sbc_audit_records_dropped` gauge stays cumulative and is never reset, so a drop burst that ends more than 60 s before a health poll is visible only in the counter: operators must alert on the rate of increase of `sbc_audit_records_dropped`, not on health status alone. Gauges `sbc_audit_records_dropped`, `sbc_audit_writer_alive` and `sbc_emergency_calls_admitted` are refreshed in gRPC `GetMetrics`. On shutdown, after `SystemShutdown`, `runtime.rs` calls `uc_audit::flush` with a 2 s deadline (it retries queuing its marker until the deadline, so a full queue is waited on). Records still queued when the deadline passes are lost. Tests: `queue_full_drops_are_counted_and_chain_stays_contiguous`, `concurrent_writers_keep_contiguous_verified_chain_and_flush_drains`, `flush_with_full_queue_waits_for_drain`, `writer_dead` tests (`uc-audit/tests/`), `global_logger_queues_records_in_order_with_hash_chain`, `health_and_metrics_expose_audit_pipeline_and_emergency_admissions`, `writer_drop_recency` (`uc-audit/tests/writer_drop_recency.rs`), `elapsed_since_encodes_never_as_none`, `audit_status_recovers_after_drop_window`, `qa_audit_status_window_boundary`. Not tested: the health endpoint JSON for a degraded `audit` component over HTTP, and the metrics gauge after recovery (its source is unchanged). |
| AU-8 | Time Stamps | **Wired (sbc-daemon)**, opt-in | `uc-audit::record` UTC timestamps on every record. |
| AU-9 | Protection of Audit Information | **Wired (sbc-daemon)**, opt-in | `uc-audit::record` SHA-384 hash chain across records (`AuditRecord::verify`); file permissions are the platform's. |
| AU-10 | Non-repudiation | Planned | Cryptographic signing of audit records |

### CP - Contingency Planning

| Control | Title | Status | Implementation |
|---------|-------|--------|----------------|
| CP-8 | Telecommunications Services | **Wired (sbc-daemon)**, partial | Trunk failover within the selected route groups (`sbc-daemon/src/sip_stack.rs` `is_failover_status`, `try_failover`, `on_invite_sent`; `uc-routing/src/router.rs` `route_to_groups`, capped by `routing.max_failover_attempts`). Triggers: 408, Timer B, 500, 502, 503, 504, a trunk URI that does not resolve, and a transport error on the **first send** of a B-leg INVITE (UDP send error, TCP/TLS connect/handshake/write failure, 30 s send timeout), which fails over immediately instead of waiting for Timer B. The failed transaction is removed before failover, the attempt counts as `TrunkOutcome::Failed` with no cooldown, and failover happens at most once per attempt; with no target left the caller gets 503. Send failures of retransmissions, ACK, CANCEL and in-dialog requests are log-only. No failover on other 4xx or 6xx, or after a 2xx or a reliable 18x carrying SDP has been relayed. A 503 puts the trunk into cooldown for its `Retry-After` delta-seconds when present (clamped to `general.trunk_retry_after_max_secs`, honoured down to 1 s), else `cooldown_secs`; missing, 0 or malformed values fall back to `cooldown_secs` (`retry_after_cooldown`, applied in `try_failover` and `handle_error_response`). Trunks marked down by OPTIONS health (config-file trunks with `options_ping_enabled`, and API trunks) are skipped (`runtime.rs` `start_config_trunk_monitors`, `spawn_trunk_health_feed`). Tests: `failover_on_503_retries_next_trunk_with_same_sdp`, `failover_exhausted_relays_last_error_and_releases`, `timer_b_fails_over_then_408_when_exhausted`, `qa_every_failover_status_moves_call_to_second_trunk`, `qa_client_and_global_errors_never_fail_over`, `qa_failover_still_happens_after_unreliable_or_sdp_less_18x`, `no_failover_after_reliable_early_media`, `options_down_trunk_is_skipped`, `qa_trunk_marked_down_mid_call_then_up`, `send_failure_fails_over_once_without_waiting_for_timer_b`, `send_failure_with_no_trunk_left_answers_503_and_releases`, `send_result_ignored_for_non_initial_invites`, `qa_send_failure_of_cancel_ack_and_in_dialog_is_log_only`, `retransmission_send_failure_after_successful_first_send_is_log_only`, `slow_first_send_failing_after_timer_a_still_fails_over_once`, `retry_after_cooldown_honoured_clamped_or_fallback`, `failover_503_retry_after_sets_trunk_cooldown`, `final_503_without_failover_honours_retry_after`, `qa_failover_503_retry_after_short_and_with_comment`. Not tested: the `server.rs` `handle_result` wiring from a real transport error to `on_invite_sent` (code review only), and the runtime health-feed task. |

## Implementation Notes

### Documenting Controls in Code

All security-relevant code includes NIST control references in doc comments:

```rust
/// NIST 800-53 Rev5: SC-13 (Cryptographic Protection)
///
/// Computes SHA-384 hash of the input data.
pub fn sha384(data: &[u8]) -> [u8; 48] {
    // ...
}
```

### Verification

Control implementations are verified through:

1. **Unit Tests**: Each module has tests validating correct behavior (e.g. `sbc-config/src/validate.rs`, `sbc-daemon/src/sip_stack.rs` admission tests).
2. **Integration Tests**: `crates/sbc/sbc-integration-tests`. There is no `tests/compliance/` directory.
3. **Audit Logging**: Wired, opt-in via `logging.audit_enabled` (see AU-2). Without it, security events are visible only in `tracing` output.
