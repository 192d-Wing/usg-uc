# NIST 800-53 Rev5 Control Implementation Matrix

This document maps NIST 800-53 Rev5 security controls to their implementations in the USG SBC codebase.

> **Status legend.** *Wired (sbc-daemon | sbc-media-core | soft client)* — a shipped binary has a call site for this (the binary is named). *Library-only* — implemented and tested in a `proto-*`/`uc-*` crate, but no shipped binary calls it. *Planned* — not implemented. A row that says only "Full"/"Complete" describes crate-level capability; the wiring column/annotation says what the running SBC actually does.

Crate names below are the real workspace crates (`crates/uc/uc-*`, `crates/proto/proto-*`, `crates/sbc/*`). There are no `sbc-crypto`, `sbc-audit`, `sbc-acl`, `sbc-registrar` or similar crates.

## Control Families

### AC - Access Control

| Control | Title | Status | Implementation |
|---------|-------|--------|----------------|
| AC-3 | Access Enforcement | **Wired (sbc-daemon)** | INVITE source admission: the source IP must belong to a configured trunk or an active registration contact (`sbc-daemon/src/sip_stack.rs`, `is_admitted_source`). The `uc-acl` crate is Library-only (no shipped binary depends on it). |
| AC-6 | Least Privilege | Planned (general); **Wired (sbc-api-server)** for CDR endpoints only | `uc-acl` crate exists (Library-only); not wired into any binary. The only least-privilege split in a shipped binary is the CDR `cdr:read` / `cdr:export` permission pair in `sbc-api-server`; see [Call Detail Records](#call-detail-records-uc-cdr-sbc-daemon-sbc-api-server) (AC-3 / AC-6 row). |

### AU - Audit and Accountability

| Control | Title | Status | Implementation |
|---------|-------|--------|----------------|
| AU-2 | Event Logging | **Wired (sbc-daemon)**, opt-in | With `logging.audit_enabled`, `sbc-daemon` initialises `uc-audit` (`runtime.rs`) and records startup/shutdown, REGISTER authentication outcomes, INVITE admission/VPS rejections, emergency-bypass grants, call establishment/termination and rate-limit rejections (`sip_stack.rs`, `server.rs`). Trunk failover is recorded as `TrunkFailover` (`sip_stack.rs` `try_failover`, emitted after the router guard is dropped) with reason 503/5xx status, `timeout` (Timer B) or `transport_error`. Trunk reachability changes are recorded as `TrunkReachabilityChanged` with source `options` (runtime OPTIONS health feed, `runtime.rs`) or `agent` (gRPC `trunk_status_publish_service.rs`), both through `SipStack::apply_trunk_reachability_change`. Tests: `status_failover_is_audited_with_status_reason`, `qa_timer_b_failover_is_audited_with_timeout_reason`, `send_failure_fails_over_once_without_waiting_for_timer_b` (transport_error), `reachability_change_is_audited` (calls the shared helper directly; the runtime and gRPC call sites are not driven by a test). Off by default. |
| AU-3 | Content of Audit Records | **Wired (sbc-daemon)**, opt-in | `uc-audit::record` structured records (sequence, UTC timestamp, typed event, hash chain) written for every event above. `AuthorizationDecision` has an additive optional `source_ip` (`uc-audit/src/event.rs`; omitted from JSON when absent, old records still deserialise), populated at every `AuthorizationDecision` site in `sip_stack.rs`: source-admission, `vps:*`, `no-usable-trunk`, `number-translation-invalid`, `max-registrations` and `emergency-bypass`. New `System`-category events: `TrunkFailover { call_id, group_id, failed_trunk_id, reason, next_trunk_id }` and `TrunkReachabilityChanged { trunk_id, reachable, source }` (`event.rs`). Tests: `authorization_decision_source_ip_is_additive`, `trunk_events_serialize_and_categorize`, `denials_carry_source_ip_in_audit`, `emergency_call_placed_while_callee_cap_max_calls_and_trunks_full`. |
| AU-4 | Audit Log Storage Capacity | **Wired (sbc-daemon)**, opt-in | `uc-audit::sink::FileSink` appends JSON lines to `logging.audit_path`; without a path records go to the tracing output (target `audit`). Rotation/retention is the platform's. |
| AU-5 | Response to Audit Logging Process Failures | **Wired (sbc-daemon)**, opt-in | Audit hand-off is non-blocking: `uc_audit::log_event` only `try_send`s onto a bounded queue of `AUDIT_QUEUE_CAPACITY = 4096` records drained by a dedicated `uc-audit-writer` thread, which assigns sequence numbers and the hash chain in queue order (`uc-audit/src/lib.rs`). Failure response: when the queue is full or the writer has exited, the record is **dropped and counted** (`dropped_records()`), and `log_event` emits a `tracing::error!` rate-limited to once per 10 s. A guard clears `writer_alive()` when the writer exits, including by panic. The daemon health check has an `audit` component: unhealthy when the writer is dead; degraded only while the most recent drop is less than `AUDIT_DROP_DEGRADED_WINDOW` (60 s, a constant, not configurable) old, then healthy again (`api_server.rs` `audit_status_from`/`audit_component_status`, using `uc_audit::last_drop_elapsed()`). The `sbc_audit_records_dropped` gauge stays cumulative and is never reset, so a drop burst that ends more than 60 s before a health poll is visible only in the counter: operators must alert on the rate of increase of `sbc_audit_records_dropped`, not on health status alone. Gauges `sbc_audit_records_dropped`, `sbc_audit_writer_alive` and `sbc_emergency_calls_admitted` are refreshed in gRPC `GetMetrics`. On shutdown, after `SystemShutdown`, `runtime.rs` calls `uc_audit::flush` with a 2 s deadline (it retries queuing its marker until the deadline, so a full queue is waited on). Records still queued when the deadline passes are lost. Tests: `queue_full_drops_are_counted_and_chain_stays_contiguous`, `concurrent_writers_keep_contiguous_verified_chain_and_flush_drains`, `flush_with_full_queue_waits_for_drain`, `writer_dead` tests (`uc-audit/tests/`), `global_logger_queues_records_in_order_with_hash_chain`, `health_and_metrics_expose_audit_pipeline_and_emergency_admissions`, `writer_drop_recency` (`uc-audit/tests/writer_drop_recency.rs`), `elapsed_since_encodes_never_as_none`, `audit_status_recovers_after_drop_window`, `qa_audit_status_window_boundary`. Not tested: the health endpoint JSON for a degraded `audit` component over HTTP, and the metrics gauge after recovery (its source is unchanged). |
| AU-8 | Time Stamps | **Wired (sbc-daemon)**, opt-in | `uc-audit::record` UTC timestamps on every record. |
| AU-9 | Protection of Audit Information | **Wired (sbc-daemon)**, opt-in | `uc-audit::record` SHA-384 hash chain across records (`AuditRecord::verify`); file permissions are the platform's. |
| AU-10 | Non-repudiation | Planned | Cryptographic signing of audit records. Neither the uc-audit chain nor the CDR SHA-384 chain and sidecars provide AU-10: both are unkeyed and unsigned (CDR signing is POA&M-13). |

### Call Detail Records (uc-cdr, sbc-daemon, sbc-api-server)

CDRs (schema v1) are a second audit trail next to uc-audit. `uc-cdr` provides the record, formats, hash chain, PII policy, ring and sinks. `sbc-daemon/src/cdr.rs` and `sip_stack.rs` emit the records. `sbc-daemon/src/grpc_server/cdr_service.rs` serves them over gRPC. `sbc-api-server/src/handlers/cdrs.rs` and `authmw.rs` serve them over REST. `[cdr]` is enabled by default. Rows here describe CDR behaviour only; the uc-audit rows above are unchanged. No test runs a real daemon process with SIP endpoints, REST through sbc-api-server, or a real TLS handshake on the gRPC or syslog channels. The daemon-level tests drive `SipStack` with a file sink.

| Control | Title | Status | Implementation |
|---------|-------|--------|----------------|
| AU-2 / AU-12 | Event Logging / Audit Record Generation | **Wired (sbc-daemon)**, on by default | One CDR per call when it ends. Answered, cancelled, busy/trunk 4xx-6xx, Timer B, transport error, media failure and shutdown endings emit through `finish_call_record` / `cleanup_terminated_call` (`sip_stack.rs`). Reject CDRs (`CdrContext::emit_rejected`, `cdr.rs`) are written for 503 draining, 503 `reject_new_calls`, 503 `max_calls`, VPS rejects, 503 no usable trunk, 500 invalid translation and the no-route announcement. They are de-duplicated per Call-ID: a bounded FIFO of 8192 entries with a 32 s TTL. ACL/DoS drops and the source-admission 403 produce no CDR; the 403 is audited only in uc-audit (`audit_invite_denied`). A 401/407 trunk challenge produces a CDR only with `record_auth_challenges = true`. `record_unanswered = routed` skips pre-store rejects, and `none` skips every unanswered call. Disabling `[cdr]` is an AU-12 deviation. Tests: `cdr_answered_then_caller_bye`, `cdr_answered_then_callee_bye_with_q850`, `cdr_cancel_before_answer`, `cdr_trunk_busy`, `cdr_timer_b_on_last_trunk`, `cdr_media_failure_after_answer`, `cdr_failover_then_answer_lists_trunk_attempts`, `cdr_bye_cancel_race_emits_exactly_one`, `cdr_trunk_407_is_not_recorded_unless_configured`, `cdr_register_challenge_is_not_recorded`, `cdr_reject_sites` (403 produces no CDR; a 503 INVITE sent three times produces one CDR), `cdr_no_route_announcement_is_a_reject`, `cdr_no_usable_trunk_is_a_no_route_reject`, `cdr_record_unanswered_routed_skips_rejects`, `cdr_shutdown_ends_remaining_calls`. Gaps: no `operator_terminated` CDR (POA&M-18); no takeover CDRs and no BYEs at shutdown (POA&M-19). |
| AU-3 | Content of Audit Records | **Wired (sbc-daemon, sbc-api-server)** | `uc-cdr/src/record.rs` `CallRecord` carries: A and B Call-IDs; caller; callee dialed and translated; `caller_translated` (the B-leg From user after manipulation, when it differs); source IP, port and transport; zones; trunk group; `trunks_tried` with per-attempt outcome; final trunk; failover count; setup, ring, answer and end times; duration; PDD; disposition; final SIP status; release side and cause; RFC 3326 Q.850 cause; media node; codec; SRTP suite; emergency flag; `node_id`; and `sequence`. `stir_attestation` is always unset in v1. `failover_takeover` is never set (no takeover path). SCTP A-legs are recorded as `tcp` (POA&M-20). Strings are capped (`sanitize`). Access events use `uc-audit` `CdrExport{user, filter, count, format, outcome, on_behalf_of}`. `outcome` and `on_behalf_of` are additive serde-default fields. Tests: `answered_call_content_is_correct_on_disk`, `qa_cdr_answered_translated_call_on_disk`, `qa_cdr_answered_emergency_call_flagged`, `cdr_caller_translated_from_b_leg_from`, `cdr_hostile_from_is_capped_and_valid_json`, `sanitize_caps_strings_on_char_boundary`, `round_trip` / `rejects_bad_enums` (`sbc-grpc-api/src/cdr.rs`), `cdr_export_is_authorization_and_outcome_is_additive`. |
| AU-4 | Audit Log Storage Capacity | **Wired (sbc-daemon)**, partial | Capacity is bounded only by retention against the volume size. `validate.rs` rejects `retention_files = 0` together with `retention_days = 0` (test `cdr_unlimited_retention_rejected`). The Helm chart mounts a dedicated 1 GiB `-cdr` PVC with 48 files x 16 MiB (test `qa_helm_cdr_retention_fits_its_volume`). There is no free-space check or capacity-threshold alert (POA&M-14). |
| AU-5 / AU-5(4) | Response to Audit Logging Process Failures | **Wired (sbc-daemon)** | Fail closed at startup: an unwritable directory stops the daemon with `RuntimeError::InitFailed{component:"cdr"}` (`runtime.rs`; tests `unwritable_directory_fails_closed`, `unwritable_directory_error_names_directory_and_keys`). The resume logic does not reuse record IDs. It fails startup when none of the 8 newest files holds a complete record (`sink.rs`; tests `unreadable_newest_files_fail_closed`, `torn_last_line_does_not_reset_sequence`, `csv_resume_after_row_with_embedded_newline`, `csv_resume_parses_quoted_newlines_and_skips_torn_row`). At runtime, emission is non-blocking (`try_send`). Queue-full and writer-dead drops are counted. Health is `Degraded` for 300 s after a drop and `Unhealthy` when the writer is dead or a file write failed within 60 s. The `cdr` health component and `sbc_cdr_*` gauges report it (`api_server.rs`). Tests: `burst_drops_without_blocking_and_degrades_health`, `health_transitions_write_error_and_writer_dead`, `queue_full_drops_and_counts`, `writer_panic_clears_alive`, `health_and_metrics_expose_cdr_pipeline`. With `on_failure = reject_new_calls`, non-emergency INVITEs get 503 with Retry-After while the component is Unhealthy, audited with policy `cdr-unavailable`; emergency calls are admitted (tests `cdr_reject_new_calls_admits_emergency_only`, `cdr_continue_mode_admits_while_unhealthy`). Each secondary (syslog) sink has its own thread and a 4096-record queue. Its drops increment `CdrStats::sink_dropped`, exported as `sbc_cdr_syslog_dropped_total` (tests `stalled_syslog_does_not_delay_file_writes`, `sink_panic_does_not_stop_the_file_writer`; no test asserts the gauge name). Sink failures and rotations are raised as uc-audit `CdrSinkFailure` and `CdrFileRotated` (test `observer_raises_audit_events`). AU-5(1) is not met (POA&M-14). |
| AU-6 | Audit Record Review, Analysis, and Reporting | **Wired (sbc-daemon, sbc-api-server, sbc-cli, sbc-dashboard)** | gRPC `CdrService` `ListCdrs` / `GetCdr` / `GetCdrStats` (`cdr_service.rs`; proto `sbc-grpc-api/proto/cdr.proto`). REST `GET /api/v1/cdrs`, `/cdrs/{record_id}`, `/cdrs/stats` and `/cdrs/export` (`handlers/cdrs.rs`; at most 50 000 records, one export per replica, otherwise 429). CLI `sbc-cli cdrs list\|show\|export\|verify`. Dashboard `Cdrs.tsx`. Reads come from the node's in-memory ring (per node, at most `ring_capacity` records); the files are the durable record. There is no delete or purge RPC. Tests: `list_and_get_cdrs`, `list_rejects_bad_input`, `disabled_cdrs_fail_precondition`, `ring_paging_through_emitter`, `paging_and_filter`, `evicts_oldest`, `list_request_parses_and_validates`, `verify_passes_then_fails_on_tamper`, `config_to_file_to_verify_to_ring`. |
| AU-8 | Time Stamps | **Wired (sbc-daemon)** | All record times are UTC epoch milliseconds from the system clock (`uc-cdr/src/sink.rs` `now_ms`, `sbc-daemon/src/cdr.rs`). File names use UTC `YYYYmmddTHHMMSS`. Syslog TIMESTAMP is RFC 3339 UTC with milliseconds and `Z` (`sink.rs`, `format("%Y-%m-%dT%H:%M:%S%.3fZ")`). Clock synchronisation is the platform's. Tests: `qa_cdr_answered_translated_call_on_disk` (setup <= ring <= answer <= end ordering, duration, PDD), `time_rotation_with_fake_clock`. No test asserts the syslog timestamp form. |
| AU-9 | Protection of Audit Information | **Wired (sbc-daemon)**, partial: tamper-evident only | `uc-cdr/src/chain.rs`: an unkeyed SHA-384 chain, `hash = SHA-384(prev_hash \|\| canonical JSON with hash="")`, plus a `<file>.sha384` sidecar for each closed file. Anyone with write access to the directory can rewrite records, chain and sidecars together. The anchor is external: uc-audit `CdrFileRotated{file, sha384}` events (only when the uc-audit chain is enabled and forwarded) or the syslog sink. Files are 0640 in a 0750 directory. `sbc-cli cdrs verify` checks the chain across files and the sidecars, and prints that the files are unanchored. CSV files are covered by the sidecar only. Not AU-10 (POA&M-13). |
| AU-9(2) | Store on Separate Physical Systems | **Wired (sbc-daemon)**, opt-in (`cdr.syslog.enabled = false` by default) | RFC 5424 records with RFC 6587 octet counting over RFC 5425 TLS (`uc-cdr/src/sink.rs` `SyslogSink`). `sbc-daemon/src/cdr.rs` `TlsSyslogConnector` uses TLS 1.3 only through `uc_transport::tls::create_client_config`. It has a 5 s connect timeout and 2 s I/O timeouts. CA trust comes from `cdr.syslog.ca_path` or `security.tls_ca_path`; there is no system trust store. DNS goes through `CollectorResolver`: at most one lookup in flight, and the last good address is reused. The sink runs on its own thread (see AU-5). No client certificate is presented (POA&M-15). Tests: `syslog_octet_counted_rfc5424`, `syslog_sink_octet_counted_frames_via_fake_connector`, `syslog_backoff_after_connect_failure`, `tls_target_parses`, `hung_resolver_keeps_one_lookup_in_flight`, `resolver_falls_back_to_last_good_address`, `stalled_syslog_does_not_delay_file_writes`. | AU-11 | Audit Record Retention | **Wired (sbc-daemon)** | `sink.rs` `apply_retention` deletes closed files, and their sidecars, beyond `retention_files` or older than `retention_days`. The open file is never deleted. Retention keys hot-reload on SIGHUP. Defaults: 168 files / 90 days (Helm: 48 / 90). Test: `retention_by_count_and_age`. |
| SI-12 | Information Management and Retention | **Wired (sbc-daemon, sbc-api-server)** | `uc-cdr/src/pii.rs` provides `pii = full \| mask_caller \| hash`. Hash mode is HMAC-SHA-384 with a key of at least 48 bytes. The policy is applied before the chain, so raw numbers never reach the file or ring. The key file is opened `O_NOFOLLOW \| O_NONBLOCK`; it must be a regular file with `mode & 0o077 == 0` (0600 or 0400), checked by `fstat` on the open handle. Symlinks, FIFOs and group- or world-readable keys are refused, and the daemon will not start. Symlinked parent directories and owner uid are not checked (POA&M-24). In CDR access audit events (sbc-api and daemon), caller and callee filters are logged as `<redacted>`. CDR content is not written to tracing. CSV formula guard (SI-10): `csv_formula_injection_end_to_end`. |
| AC-3 / AC-6 | Access Enforcement / Least Privilege | **Wired (sbc-api-server, sbc-daemon)** | sbc-api `authmw.rs` `Principal`: the legacy admin credential holds both permissions. An OIDC operator gets `cdr:read` from role `cdr-reader`, `auditor`, `cdr-exporter` or `fleet-admin`, or from scope `cdr:read`. It gets `cdr:export` from `cdr-exporter` or `fleet-admin`, or from scope `cdr:export`. `config-admin` alone gets 403. Route layers `require_cdr_read` / `require_cdr_export` return 403 and audit an `AuthorizationDecision` deny (policy `cdr-rbac`, user or `anonymous`). Daemon: `CdrService` is mounted only with `grpc.require_mtls` or a loopback listener (`grpc_server/mod.rs` `cdr_service_permitted`). Under mTLS, `ClientCertGate` (`grpc_server/peer_identity.rs`, applied to every gRPC service) admits only certificates whose SAN DNS, SAN URI or subject CN is in `grpc.allowed_client_names`. Otherwise it returns `PERMISSION_DENIED`, audited with policy `grpc.allowed_client_names`. An empty list admits any certificate that chains to the CA, with a startup warning. The daemon does no per-user permission check: it trusts sbc-api's gate. The audited principal is `cert:<name>@peer`; `x-sbc-user` is recorded only as `on_behalf_of`. On loopback without mTLS, access is unauthenticated (`unauthenticated@peer`; POA&M-22). Tests: `cdr_permissions_from_claims`, `cdr_routes_deny_without_permission`, `cdr_denial_is_audited_with_user`, `cdr_service_only_on_mtls_or_loopback_listener`, `allow_listed_cert_accepted_with_cert_principal`, `other_cert_rejected`, `missing_or_garbage_cert_rejected`, `empty_allow_list_admits_chained_cert_named_by_subject`, `cn_walker_is_bounds_checked`, `gate_without_mtls_passes_through`, `audit_principal_is_the_client_certificate`, `allowed_client_names_without_mtls_rejected`, `malformed_allowed_client_names_rejected`. |
| IA-3 / SC-8 | Device Identification and Authentication / Transmission Confidentiality | **Wired (sbc-api-server, sbc-daemon)**, opt-in (`sbcDaemon.grpcMtls.enabled = false` by default) | sbc-api dials the daemon over mTLS when all three of `SBC_DAEMON_GRPC_TLS_{CA,CERT,KEY}_FILE` are set (`sbc-api-server/src/config.rs`, `state.rs`). The daemon requires client certificates under `grpc.require_mtls` and checks them against `allowed_client_names` (see AC-3). Helm `26-sbc-grpc-mtls.yaml` issues ECDSA P-384 server and client certificates through cert-manager, or uses operator Secrets. SC-13 is **not** claimed for this channel: both ends use tonic's default rustls suites (POA&M-16). The trunk agent and sbc-cli have no gRPC TLS client (POA&M-17). ### CP - Contingency Planning

| Control | Title | Status | Implementation |
|---------|-------|--------|----------------|
| CP-8 | Telecommunications Services | **Wired (sbc-daemon)**, partial | Trunk failover within the selected route groups (`sbc-daemon/src/sip_stack.rs` `is_failover_status`, `try_failover`, `on_invite_sent`; `uc-routing/src/router.rs` `route_to_groups`, capped by `routing.max_failover_attempts`). Triggers: 408, Timer B, 500, 502, 503, 504, a trunk URI that does not resolve, and a transport error on the **first send** of a B-leg INVITE (UDP send error, TCP/TLS connect/handshake/write failure, 30 s send timeout), which fails over immediately instead of waiting for Timer B. The failed transaction is removed before failover, the attempt counts as `TrunkOutcome::Failed` with no cooldown, and failover happens at most once per attempt; with no target left the caller gets 503. Send failures of retransmissions, ACK, CANCEL and in-dialog requests are log-only. No failover on other 4xx or 6xx, or after a 2xx or a reliable 18x carrying SDP has been relayed. A 503 puts the trunk into cooldown for its `Retry-After` delta-seconds when present (clamped to `general.trunk_retry_after_max_secs`, honoured down to 1 s), else `cooldown_secs`; missing, 0 or malformed values fall back to `cooldown_secs` (`retry_after_cooldown`, applied in `try_failover` and `handle_error_response`). Trunks marked down by OPTIONS health (config-file trunks with `options_ping_enabled`, and API trunks) are skipped (`runtime.rs` `start_config_trunk_monitors`, `spawn_trunk_health_feed`). Tests: `failover_on_503_retries_next_trunk_with_same_sdp`, `failover_exhausted_relays_last_error_and_releases`, `timer_b_fails_over_then_408_when_exhausted`, `qa_every_failover_status_moves_call_to_second_trunk`, `qa_client_and_global_errors_never_fail_over`, `qa_failover_still_happens_after_unreliable_or_sdp_less_18x`, `no_failover_after_reliable_early_media`, `options_down_trunk_is_skipped`, `qa_trunk_marked_down_mid_call_then_up`, `send_failure_fails_over_once_without_waiting_for_timer_b`, `send_failure_with_no_trunk_left_answers_503_and_releases`, `send_result_ignored_for_non_initial_invites`, `qa_send_failure_of_cancel_ack_and_in_dialog_is_log_only`, `retransmission_send_failure_after_successful_first_send_is_log_only`, `slow_first_send_failing_after_timer_a_still_fails_over_once`, `retry_after_cooldown_honoured_clamped_or_fallback`, `failover_503_retry_after_sets_trunk_cooldown`, `final_503_without_failover_honours_retry_after`, `qa_failover_503_retry_after_short_and_with_comment`.
