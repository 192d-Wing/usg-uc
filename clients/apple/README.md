# Apple client (iOS + macOS)

Phase 1 of `docs/CLIENT-NATIVE-MIGRATION-PLAN.md`: the SwiftUI shell over the
shared Rust core, consumed through the `client-ffi` UniFFI layer.

## Layout

- `build-xcframework.sh` — builds `client-ffi` staticlibs (macOS arm64, iOS,
  iOS simulator), generates the Swift bindings, and assembles
  `ClientFFI.xcframework` into the Swift package. Run this first; the
  framework and `ClientFFI.swift` are generated, not committed.
- `build-ios-app.sh` — builds the iOS app for the iOS Simulator (runs
  `build-xcframework.sh`, regenerates the Xcode project with xcodegen, then
  `xcodebuild`).
- `UsgSipClient/` — Swift package:
  - `UsgSipClient` library target: generated bindings + the Rust binary target
  - `SipClientDemo` executable: minimal SwiftUI smoke-test app (macOS)
  - `SipClientApp` executable: the SwiftUI client (macOS). Its
    `Sources/SipClientApp/*.swift` are cross-platform (`#if os(macOS)` /
    `#if os(iOS)`) and are reused as-is by the iOS app target.
- `ios/` — iOS app:
  - `project.yml` — xcodegen spec for the `SipClientApp-iOS` app target. It
    reuses the same SwiftUI sources as the macOS executable and depends on the
    `UsgSipClient` SwiftPM library product + `ClientFFI.xcframework`.
  - `Info.plist` — `NSMicrophoneUsageDescription`, `UIBackgroundModes`
    (audio, voip), launch screen.
  - `LaunchScreen.storyboard` — minimal launch screen.
  - `SipClientApp-iOS.xcodeproj` is generated by xcodegen, not committed.

## Quick start

```sh
./build-xcframework.sh            # add --release for optimized core
cd UsgSipClient
swift build                       # link check
swift run SipClientDemo           # macOS smoke-test UI
```

The demo reads the same `settings.toml` as the desktop client
(`~/Library/Application Support/com.usg.sip-client/`), so an account
configured there auto-registers on launch.

Microphone permission for `swift run` is inherited from the terminal app
(System Settings → Privacy & Security → Microphone), same as `cargo run`.

## iOS app

Needs [xcodegen](https://github.com/yonaskolb/XcodeGen): `brew install xcodegen`.

```sh
./build-ios-app.sh                # framework + xcodegen + simulator build
```

Or step by step:

```sh
./build-xcframework.sh            # needs the iOS slices (don't pass --skip-ios)
cd ios
xcodegen generate                 # (re)generate SipClientApp-iOS.xcodeproj
xcodebuild -project SipClientApp-iOS.xcodeproj -scheme SipClientApp-iOS \
    -destination 'generic/platform=iOS Simulator' build
```

To run it in the simulator:

```sh
xcrun simctl boot 'iPhone 15' || true          # any device from `simctl list devices available`
xcodebuild -project ios/SipClientApp-iOS.xcodeproj -scheme SipClientApp-iOS \
    -destination 'platform=iOS Simulator,name=iPhone 15' build
APP=$(xcodebuild -project ios/SipClientApp-iOS.xcodeproj -scheme SipClientApp-iOS \
    -destination 'platform=iOS Simulator,name=iPhone 15' -showBuildSettings \
    | awk -F' = ' '/ CODESIGNING_FOLDER_PATH /{print $2}')
xcrun simctl install booted "$APP"
xcrun simctl launch booted org.jhics.usgsipclient
```

The iOS app configures `AVAudioSession` (`.playAndRecord` / `.voiceChat`)
before the Rust audio backend starts. Registration against BulkVS needs an
account configured in the app's data dir, which a fresh simulator won't have —
launching without crashing is the smoke-test bar.
