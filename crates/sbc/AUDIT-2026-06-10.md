# crates/sbc Full Audit — 2026-06-10

Scope: sbc-daemon, sbc-config, sbc-cli, sbc-grpc-api, sbc-integration-tests, sbc-dashboard
(~19,200 lines Rust + ~1,800 lines TS/TSX). Five parallel subsystem reviews plus
`cargo audit`, `npm audit`, and clippy. Findings are deduplicated and ordered by severity.

---

## Critical

### C1. Management plane has no authentication or authorization at all
**Files:** `sbc-daemon/src/api_server.rs:389-476` (router has only `TraceLayer`), `sbc-daemon/src/runtime.rs:331-334,564`, `sbc-daemon/src/grpc_server/mod.rs:162-172`
Independently confirmed by three reviewers. The REST API binds `0.0.0.0:8080` by default, plain HTTP (`runtime.rs` constructs `ApiServerConfig` with `tls: None`, so `run_http()` is always taken). The gRPC server (`:9090`) defaults to no TLS and has no auth interceptor; mTLS is the only possible control and is off by default. Every mutating endpoint is open to any network client: user/credential CRUD, trunk group CRUD, registration deletion, phone reboot, TLS reload, cluster drain.
**Fix:** Auth middleware (bearer/mTLS/session) on the `/api` nest and a tonic interceptor; require TLS for the management listener or default binds to `127.0.0.1`.

### C2. Credential disclosure through the unauthenticated API
- **Digest HA1 returned by user endpoints** — `api_server.rs:1414-1426` (`get_user`), `1361-1371` (`list_users`) serialize the full `User` including `digest_ha1` (password-equivalent for SIP digest). Fix: `#[serde(skip_serializing)]` or a sanitized DTO.
- **Trunk SIP passwords in plaintext, returned and persisted world-readable** — `api_server.rs:991-1008` (GET responses include `sip_password`), `api_server.rs:139-157` (`save_trunk_groups` → `std::fs::write` `/var/lib/sbc/trunk_groups.json` with default 0644 perms). Fix: redact from GETs, write with mode 0600, encrypt at rest (the AES-256-GCM HA1 machinery already exists for the user store).
- **Phone provisioning serves SIP passwords keyed only by MAC** — `api_server.rs:1567-1647` (`GET /provision/{*path}`), generated configs embed `sip_password` (`uc-phone-mgmt/src/cisco_mpp.rs:35`, `teo.rs:151`). MACs are low-entropy/guessable; no auth, no rate limit. Fix: provisioning token or client cert, TLS only, source-network restriction, rate limiting.
- **Full SIP auth exchanges logged at `info!`** — `trunk_registrar.rs:215-237, 308-326` logs REGISTER/Authorization headers (digest responses are offline-bruteforceable). Fix: move to `trace!` and redact `Authorization`/`Proxy-Authorization`.

### C3. RTP relay is a blind plaintext forwarder — no SRTP, no source validation
**File:** `sbc-daemon/src/media_pipeline.rs:902-1010` (`start_relay`)
Relay tasks copy bytes socket-to-socket. They never invoke the SRTP protect/unprotect path despite `srtp_required: true` default, and `Ok((n, _src))` discards the packet source — anyone who learns the advertised media port can inject or overwrite the RTP stream.
**Fix:** Validate source (or implement symmetric-RTP latching) and route packets through SRTP before forwarding.

## High

### H1. Unbounded attacker-keyed state + no rate limiting (unauthenticated DoS)
- `announcement_calls` (`sip_stack.rs:186`, inserted `:2150`, never removed) — every INVITE to an unroutable number adds a permanent entry.
- `TransactionStore` INVITE maps (`sip_stack.rs:1461,1473`) — never removed, even on normal teardown.
- `sequence_trackers` (`media_pipeline.rs:799`) — keyed by attacker-controlled RTP SSRC, never pruned.
- No per-source rate limiting or call cap anywhere in `process_message` (`sip_stack.rs:586-612`); config has `global_rps`/`per_user_rps` but only `per_ip_rps` is wired (`server.rs:173-181`).
**Fix:** Remove transaction/announcement entries on terminal states; bound SSRC trackers per session; token-bucket per source + concurrent-call ceiling before allocating state.

### H2. Trunk identity trusted from bare source IP (spoofable)
**File:** `sip_stack.rs:1245-1268, 2047-2049` (`lookup_inbound_trunk`)
Inbound trunk identity and its CSS/routing privileges are resolved solely from the UDP source IP, which is spoofable off-path. **Fix:** authenticated transport (digest/mTLS/IPsec) for trunk identification.

### H3. Graceful shutdown drain is a no-op
**Files:** `shutdown.rs:201-265`, `runtime.rs:635`, `server.rs:377-380`
`ConnectionTracker::call_started()` etc. are only ever called from tests — `total_active()` is always 0, so drain "succeeds" instantly and active calls are killed on SIGTERM. Even if wired, receive loops are aborted *before* drain, so BYEs that would end calls can't be processed. **Fix:** wire the tracker to real dialog lifecycle; keep receive loops alive (rejecting new INVITEs) until drained.

### H4. Trunk monitor/registrar side-channel sockets on live :5060 — inbound call hijack + flaky health
**Files:** `trunk_monitor.rs:244-304`, `trunk_registrar.rs:164-239`
OPTIONS/REGISTER are sent from throwaway sockets bound to `zone_ip:5060` with SO_REUSEADDR/REUSEPORT next to the main listener. On Linux, specific-IP binds steal datagrams from the wildcard listener — inbound INVITEs can land on the temp socket and be discarded during each 5s recv window; responses can be misdelivered, producing false trunk-down. `recv_from` also accepts the first datagram from *any* source with no branch/Call-ID/source matching. **Fix:** send via the main transport/transaction layer; match responses by Via branch + Call-ID.

### H5. Trunk monitor/registration tasks leak, duplicate, and can't be stopped
**Files:** `trunk_monitor.rs:147-218`, `trunk_registrar.rs:68-145`; call sites `api_server.rs:1116,1153,1173`, `runtime.rs:541`
Infinite-loop tasks whose JoinHandles are dropped; every trunk PUT spawns another registration loop (the old one keeps re-REGISTERing with stale credentials). Delete/disable never stops loops; nothing aborts them at shutdown. **Fix:** `HashMap<trunk_id, JoinHandle>`, abort-before-spawn, `stop_trunk()`, shutdown subscription.

### H6. Re-registration timer ignores server-granted Expires
**File:** `trunk_registrar.rs:136-142`
The granted expires is parsed (`:337-347`) but the scheduler uses configured expires only. If the carrier grants 120s against a configured 3600s, the SBC is unreachable for inbound calls for ~48 minutes per cycle. No backoff/jitter on failure either. **Fix:** `min(granted, configured) * 80%`; exponential backoff on failure.

### H7. SIGHUP hot reload is a no-op
**File:** `runtime.rs:682-720` (vs snapshot clone at `:258`)
The reload loop writes into `Arc<RwLock<SbcConfig>>`, but every component (Server, rate limiter, SipStack, transports, API) was built from a startup value clone and never re-reads it. The log claims "Configuration reloaded successfully". **Fix:** propagate via `watch::Receiver` or shared Arc; or log honestly.

### H8. Config validation covers ~⅓ of the schema; security-labeled options silently ignored
**Files:** `sbc-config/src/validate.rs:21-30`, `schema.rs` (multiple)
- Unvalidated: routing, dial plans, trunk groups, zones, header manipulation, topology hiding, gRPC, logging, monitoring. Stringly-typed enums accept anything; dangling cross-references allowed; typo'd manipulation-rule `direction` silently widens scope to "both" (`sip_stack.rs:502-506`).
- Dead-but-accepted security knobs: `min_tls_version`, `require_mtls`, `curve`, the whole `stir_shaken` section (`verification_enabled` defaults **true** with no consuming code), `logging.audit_enabled`/`audit_path`, `rate_limit.global_rps`/`per_user_rps`, `ws_listen`/`wss_listen` (validate as listeners but never bound), `general.max_calls`/`max_registrations` (logged, not enforced).
**Fix:** add validators for the missing sections (or serde-tagged enums); wire or delete dead fields; warn at startup on set-but-unimplemented options.

### H9. sbc-cli fabricates results for mutating operations
**Files:** `sbc-cli/src/commands/calls.rs:113-131`, `config.rs:131-143`, `status.rs`, `metrics.rs`, `health.rs:14-26`
`calls terminate` and `config reload` print success without contacting the daemon; `status`/`calls list`/`metrics` print invented data; `health` checks the *operator's workstation* and hardcodes `sbc_core` healthy; `--api-url` is parsed and never used. **Fix:** until the API client is wired, exit non-zero with "NOT IMPLEMENTED"; never simulate success for mutations.

## Medium

### SIP protocol correctness (sip_stack.rs)
- **In-dialog BYE/CANCEL/ACK malformed** — missing From/To (with tags) and Max-Forwards (`:1596-1604`, `:1722-1733`, `:819-831`); receiving UAs won't match the dialog → leaked far-leg dialogs/media. The announcement path (`:2203-2206`) does it correctly.
- **Hardcoded CSeq** (`:824, :1598, :1719`) — breaks re-INVITE/mid-dialog sequencing.
- **Responses matched by Call-ID only** (`:647-707`) — no Via-branch/CSeq validation; forged 200 OK injection possible. Stored client transactions are never consulted.
- **REGISTER clobbers bindings** (`:1056-1079`) — removes all bindings then re-adds one synthesized contact; breaks multi-device and resurrects de-registrations (Expires: 0).
- **No Max-Forwards / loop detection** (`:1379-1391`) — fresh `max_forwards(70)` on the B-leg; two SBCs can loop forever.
- **Error-response path leaks media sessions** (`:913-938`) — no `stop_relay`/`remove_session`.
- **Predictable tags/SSRC from timestamps** (`:2385-2392`, `media_pipeline.rs:1074-1080`) — use a CSPRNG.
- **RtpPortAllocator under/overflow** (`media_pipeline.rs:94-117`) — u16 wraparound panics/misallocation; validate range, use checked math.
- **Possible slice panic on malformed RTP** (`media_pipeline.rs:793-795`) — guard `data.get(header_size..)` instead of trusting the parser contract.

### API/runtime correctness
- **Wrong HTTP status codes** — many handlers return 200 with `{"success": false}` or errors (`api_server.rs:1006,1267-1278,1546,1559,1693,1769`); `delete_trunk` also never persists or syncs to the router (trunk reappears after restart).
- **Blocking I/O in async** — `save_trunk_groups` does sync fs writes while holding the mem_store write lock (`api_server.rs:139-157`); blocking DNS via `to_socket_addrs()` in `trunk_monitor.rs:233-240`, `trunk_registrar.rs:151-159`, `zone.rs:238-246` (use `tokio::net::lookup_host`).
- **Silent transport-task death** (`server.rs:348-382, 527-542`) — a panic in `process_message` kills a listener while `/healthz` stays green (`AlwaysHealthyCheck`; health poll loop is an empty stub). Receive loop also busy-spins at 100% CPU on persistent transport errors (`server.rs:464-470`).
- **Cluster mode not production-ready** — heartbeat/membership are comments (`cluster.rs:159-184`); cluster init failure silently falls back to standalone (`runtime.rs:73-88`) → undetectable split-brain.
- **Zones resolved but never bound** (`runtime.rs:264-304`, `server.rs:104-111`) — wildcard listeners yield `zone_name = None`, silently disabling all per-zone SIP processing; `unique_signaling_addrs()` is dead code.
- **Registrar status init race** (`trunk_registrar.rs:76-109`) — first registration result can be dropped or overwritten with "Initializing".
- **TLS status endpoints leak filesystem paths** (`api_server.rs:2043-2052`, `system_service.rs:116-117,156-157`).
- **CRLF/header injection unvalidated** — manipulation rule `header`/`value`, `topology_hiding.external_host`, `static_destination`, `trunk.host` flow from config to the wire with no control-character checks (`schema.rs:777-822` → `sip_stack.rs:509-531`).
- **No config-file permission check on load** (`sbc-config/src/lib.rs:173-180`).

### CLI/dashboard
- **CLI hand-rolled JSON output is unescaped/invalid** (`sbc-cli/src/output.rs:22-92`) — use serde_json; also `--json` mode interleaves plain println.
- **Unknown subcommands silently run a different command with exit 0** (`sbc-cli/src/args.rs:151-179`); flags after the command are silently dropped. Migrate to clap.
- **Dashboard error swallowing** (`sbc-dashboard/src/pages/Dashboard.tsx:52-64`) — per-fetch catches make the error state unreachable; daemon-down shows "Loading…" forever.
- **Registrations poll blanks table every 15s + stale-response race** (`Registrations.tsx:25-42`).
- **CDRs show full total against first-page-only data, no pagination** (`Cdrs.tsx:33-54`).
- **~600 lines of duplicated list-page boilerplate across 9 pages** — extract a `useApiList` hook + shared layout (also the right home for the stale-response/sorting fixes).

## Test coverage
`sbc-integration-tests` covers gRPC and cluster paths reasonably (983/726 lines) but has **zero coverage** for: the REST API (including the credential-disclosure endpoints), trunk registration/monitoring, zone resolution, SIP call flows, config validation gaps, and every sbc-cli command (CLI unit tests are "doesn't panic" smoke tests). `config_tests.rs` asserts `min_tls_version == "1.3"` — a field the daemon never reads.

## Overall assessment
The signaling skeleton handles the happy path, but the system is not safe to expose:
1. **The management plane (REST + gRPC) has no authentication and leaks SIP credentials** — this single gap makes most other security findings directly exploitable.
2. **The media plane forwards plaintext RTP from any source** despite advertising SRTP.
3. **Several headline features are non-functional plumbing that reports success** — graceful drain, SIGHUP reload, cluster heartbeat, STIR/SHAKEN verification, audit logging, and most of the CLI.

Suggested order of attack: C1/C2 (auth + redaction + file perms) → C3 (relay source validation/SRTP) → H1/H2 (DoS bounds, rate limiting, trunk auth) → H3–H7 (lifecycle/trunk reliability) → H8/H9 (validation honesty, CLI honesty) → mediums.
